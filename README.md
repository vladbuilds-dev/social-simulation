# Симулятор распространения слухов в социальной сети

Агентная модель: как структура сети, боты-усилители, скептики и боты-фактчекеры влияют на то, превратится ли слух в массовый каскад или затухнет.

**Вопрос исследования.** При каких условиях слух перестаёт затухать и охватывает большую часть сети? Что сильнее влияет на итог: сколько в сети ботов или где они стоят? Насколько помогают скептики и фактчекинг?

**Гипотеза.** При одинаковой доле ботов охват дезинформации выше, если боты занимают центральные узлы сети. Даже небольшая доля фактчекеров снижает охват, и сильнее всего, когда фактчекеры тоже стоят в хабах и включаются рано.

## Быстрый старт

```bash
cd ~/Desktop/social-simulation
./run.sh                      # установит зависимости (первый раз) и откроет веб-интерфейс
```

Или вручную:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

streamlit run app.py          # интерактивный симулятор в браузере
python main.py --gif          # один прогон → results/dynamics.png, network_before_after.png, spread.gif
python experiments.py         # все эксперименты (30 прогонов на точку, ~30 секунд)
```

Примеры для `main.py`:

```bash
python main.py --bots 0.05 --placement hubs
python main.py --bots 0.05 --factcheck 0.03 --factcheck-placement hubs --delay 1
python main.py --network small_world --p-share 0.35 --skeptics 0.3
```

## Модель

### Сеть
300 узлов (можно 100–800). Три типа сети:
- **scale-free** (Barabási–Albert): есть хабы, аналог крупных аккаунтов;
- **small-world** (Watts–Strogatz): плотные кластеры и немного дальних связей;
- **random** (Erdős–Rényi): связи случайные, для сравнения.

### Типы агентов

| Тип | Доля | p_exposure | p_share | p_verify | Активен шагов |
|---|---|---|---|---|---|
| Обычный пользователь | остаток | 0.35 | **p_share** (0.18) | 0.04 | 3 |
| Скептик | 15% | 0.30 | p_share × 0.15 | 0.45 | 2 |
| Инфлюенсер | 3%, самые связные узлы | 0.45 | p_share × 1.4 | 0.05 | 4 |
| Бот-усилитель | 0–10% | — | всегда публикует слух | — | не выгорает |
| Бот-фактчекер | 0–5% | — | всегда публикует опровержение | — | не выгорает, включается с задержкой |

- `p_exposure`: вероятность заметить пост соседа за шаг;
- `p_share`: вероятность поверить слуху и начать его репостить;
- `p_verify`: вероятность проверить слух и опубликовать опровержение.

### Состояния
- **сообщение:** `NONE` (ничего не принял), `RUMOR` (поверил слуху), `CORRECTION` (принял опровержение);
- **активность:** публикует ли агент своё сообщение прямо сейчас;
- **видел слух:** агент хотя бы раз заметил слух.

### Правила одного шага
1. Каждый активный агент показывает своё сообщение соседям.
2. Сосед замечает пост с вероятностью `p_exposure`.
3. **Слух.** Если сосед ещё ничего не принял, он с вероятностью `p_verify` проверяет слух, принимает опровержение и публикует его. Иначе он с вероятностью `p_share` верит слуху и начинает репостить.
4. **Опровержение.** Его принимают только те, кто уже видел слух. Репостят опровержение вдвое реже, чем слух: опровержения распространяются хуже.
5. Если за один шаг агент получил и слух, и опровержение, побеждает опровержение.
6. Люди выгорают через `lifetime` шагов. Боты не выгорают и не меняют позицию.
7. Все изменения применяются одновременно, так что порядок обхода узлов на результат не влияет.

### Метрики
- **охват слуха:** доля людей (боты не считаются), которые хоть раз поверили слуху;
- **массовый каскад:** охват больше 20%;
- **пик активных:** максимум одновременно репостящих слух и шаг, на котором он достигнут;
- **опровержение:** доля людей, принявших опровержение к концу прогона.

## Результаты (300 узлов, 30 прогонов на точку)

Полные таблицы лежат в `results/summary.md`, сырые данные в `results/*.csv`.

**1. Боты превращают затухающий слух в каскад.**

| Сценарий | Охват слуха | Пик активных |
|---|---|---|
| Без ботов | 4.0% | 5.5 |
| 5% ботов-усилителей | 22.3% | 23.5 |
| 5% ботов + 3% фактчекеров в хабах | 13.9% | 14.1 |

**2. Переломная точка** (`threshold_curve.png`). Каскад случается в половине прогонов при p_share ≈ 0.275 в scale-free и случайной сети и при ≈ 0.375 в small-world сети. Ниже порога слух почти всегда затухает, выше почти всегда разрастается.

**3. Положение важнее количества** (`bot_placement.png`). Возьмём одни и те же 3% ботов:

| Размещение | Охват | Вероятность каскада |
|---|---|---|
| Случайно | 17.8% | 23% |
| В хабах | 39.5% | 100% |
| На периферии | 16.4% | 17% |

**4. Фактчекинг работает лучше, если он ранний и стоит в хабах** (`factcheck.png`). Против 5% ботов 5% фактчекеров в хабах, включённых на первом шаге, снижают охват с 22% до 11%. Те же фактчекеры, включённые на шестом шаге, дают только 16%.

**5. Скептики сдвигают порог** (`heatmap_skeptics.png`). При p_share = 0.3 без скептиков слуху верят 38% людей, при 30% скептиков 14%, при 50% скептиков 8%.

## Ограничения

Модель иллюстративная. Она не прогнозирует поведение конкретной соцсети или конкретных людей, а сравнивает механизмы: как локальные правила и структура связей порождают коллективный эффект. Параметры подобраны вручную, модель не откалибрована на реальных данных. Выводы качественные: «хабы опаснее периферии», «ранний фактчекинг лучше позднего». Точные проценты зависят от параметров.

Бот здесь не реальный аккаунт, а абстрактный агент с фиксированным поведением. Он нужен, чтобы изучать, насколько сеть устойчива к координированному усилению, и сравнивать защитные сценарии.
